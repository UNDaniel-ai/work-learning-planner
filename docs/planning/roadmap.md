# Project Roadmap

## 0. 仓库与流程治理

状态：已完成

- 初始化 Git 仓库与 `main` 分支。
- 建立项目 README、路线图、状态记录和决策日志。
- 约定所有规划和阶段文档都进入版本控制。
- 保留 session 文档，支持后续跨聊天恢复。

## 1. 需求对齐与事实调研

状态：已完成

- 核查 GitHub 候选项目。
- 明确个人工作学习规划的核心范围。
- 记录现成项目、二次开发和从零开发的取舍。
- 确认第一版的成功标准和非目标。

当前结论：

- 立即使用：`Super Productivity`
- 自建底座首选：`Vikunja`
- 知识与复盘参考：`Logseq`
- 暂不采用：`Plane`、`OpenProject`、`Planka` 作为个人系统主底座

## 2. 技术设计

状态：已完成

需要产出：

- 方案比较：Vikunja 外挂规划层、Super Productivity 插件 / 外部面板、从零构建。
- 系统边界和数据流。
- 领域模型：领域、目标、项目、任务、学习主题、时间块、复盘。
- 第一版页面与关键工作流。
- 部署、备份、同步和许可证风险。

当前推荐：

- 独立的 Work & Learning Planner Web 应用。
- 通过 Vikunja API v2 读写执行任务。
- 本地规划数据库保存目标、学习主题、时间块、复盘和同步映射。
- 第一实现切片为“连接 Vikunja + 读取任务 + 建立一个周计划”。

## 3. 实现计划

状态：计划完成，等待用户确认

需要产出：

- 可执行的开发切片。
- 测试策略和 TDD 步骤。
- 每个切片的输入、输出和验收标准。
- 数据迁移、备份和回滚方案。

当前计划：

- 共 12 个步骤，从脚手架和配置开始，到领域模型、TaskProvider、SQLite 仓储、Vikunja 适配器、MVP 页面、导出和 e2e 验收。
- 每个非平凡步骤都包含前置输入、文件范围、验证命令、预期结果和 Step Acceptance。
- 进入编码前仍需要用户明确回复“确认开始编码”。

## 4. MVP 实现

状态：进行中

当前进度：

- 步骤 1 已完成：应用脚手架与基础质量门。
- 步骤 2 已完成：配置、环境变量与健康检查。
- 步骤 3 已完成：领域模型与纯规则。
- 步骤 4 已完成：`TaskProvider` 接口与内存实现。
- 步骤 5 已完成：SQLite 数据库 schema、仓储、迁移和数据模型文档。
- 步骤 6 已完成：规划用例服务。
- 步骤 7 已完成：Vikunja API v2 client、provider 适配器和连接测试 API。
- 下一步：步骤 8，App Shell 与导航。

候选 MVP 范围：

- 工作 / 学习两个领域。
- 目标 → 项目 → 任务层级。
- 周计划与日计划。
- 时间块或专注记录。
- 每日 / 每周复盘。
- 基础统计。

明确暂不做：

- 财务、健康、社交和完整 Life OS。
- 团队权限与复杂协作。
- 过早的 AI 自动规划。

## 5. 验收与真实使用

状态：未开始

- 使用真实工作和学习任务验证至少一个完整周计划周期。
- 验证任务创建、调整、完成、延期和复盘。
- 验证备份恢复和数据导出。
- 记录“不好用的地方”，而不是只记录功能是否存在。

## 6. 持续优化

状态：未开始

每一轮优化都记录：

- 观察到的真实问题。
- 当前假设。
- 变更方案。
- 验证方式。
- 结果与下一步。
