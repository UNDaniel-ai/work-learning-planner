# 需求对齐：学习执行与知识沉淀系统

## 1. 用户目标

用户希望现有项目除了工作 / 学习计划外，还能：

- 记录学习过程中的知识点，而不是只记录“学了多久”。
- 辅助深度阅读、理解和实际操作。
- 将学习中的问题、尝试、失败、验证和结论系统化沉淀。
- 让知识点能够和目标、任务、时间块、复盘连接起来。
- 通过一个真实项目逐步学习，而不是只看概念或收集链接。
- 让 AI 更像教练 / 助教，帮助拆解、提问、诊断和复盘，而不是直接代做。

用户给出的示例是 Stanford CS336 Assignment 1：

- 仓库：[stanford-cs336/assignment1-basics](https://github.com/stanford-cs336/assignment1-basics)
- 课程主页：[cs336.stanford.edu](https://cs336.stanford.edu/)

## 2. 本轮明确约束

- 继续使用当前项目作为统一入口，不另起一个孤立的笔记工具。
- 需求、设计、实现计划、进度、验收和学习系统本身的演进继续由 Git 追踪。
- 继续沿用当前项目的 TDD 要求。
- 首期仍然面向单人使用，不引入团队权限、协作和组织管理。
- 首期不把系统扩展成完整的 Notion、Anki、课程平台或 RAG 知识搜索平台。
- CS336 场景必须遵守其仓库中的 AI 教学边界：AI 提供解释、提问、方向、测试建议和代码审查，但不直接完成作业、补全 TODO、编辑学生仓库或运行作业命令。

## 3. 现有仓库事实

当前项目已经具备一个适合承载学习闭环的规划基础：

- 页面入口已有 `/today`、`/weekly`、`/goals`、`/review`、`/settings`。
- 领域模型已有 `areas`、`goals`、`learning_topics`、`planning_periods`、`time_blocks`、`reviews`。
- `TaskProvider` 抽象已经把外部任务执行层与本地规划层隔离。
- SQLite / Drizzle 仓储已经支持目标、学习主题、计划周期、时间块、复盘和导出。
- 当前测试体系使用 Vitest / Testing Library / Playwright，并要求产品行为走 RED -> GREEN -> Refactor。
- 当前 `learning_topics` 只有标题、进度、状态和创建时间，无法表达知识卡片、来源、问题、证据或复习。

因此本次不是从零增加一个笔记页面，而是在现有“目标 -> 计划 -> 执行 -> 复盘”闭环旁边增加一条“来源 -> 理解 -> 证据 -> 知识 -> 回忆 -> 迁移”闭环。

## 4. CS336 Assignment 1 的真实结构分析

### 4.1 仓库给出的工作方式

Assignment 1 仓库的 README 明确要求：

- 使用 `uv` 管理可复现 Python 环境。
- 使用 `uv run pytest` 执行测试。
- 初始测试应因 `NotImplementedError` 失败。
- 学生通过 `tests/adapters.py` 将自己的实现接入测试。
- 仓库同时提供课程手册、测试、fixture、snapshot 和一个预分词分块示例。

这说明学习过程不是“读完一篇文章写一段笔记”，而是：

```text
阅读规格
  -> 写出自己的实现
  -> 测试失败
  -> 通过小实验 / 不变量定位问题
  -> 测试通过
  -> 解释实现取舍和失败原因
```

### 4.2 知识主题和验证方式

从仓库的测试和适配器结构可以识别出几组学习单元：

| 学习单元 | 示例知识 | 主要证据 |
|---|---|---|
| 环境与数据 | `uv`、batch 采样、context length、CPU / CUDA 边界 | 命令输出、数据形状、失败信息 |
| Tokenizer | UTF-8 字节、special token、round-trip、迭代编码 | pytest、fixture、与 tiktoken 的对照 |
| BPE | pre-tokenization、merge、tie-breaking、特殊 token | reference vocab / merges、速度测试 |
| 神经网络原语 | Linear、Embedding、SiLU、SwiGLU、RMSNorm | snapshot、shape、不变量 |
| Attention | scaled dot-product、mask、multi-head、RoPE | snapshot、toy tensor、形状和数值检查 |
| Transformer | pre-norm block、LM forward、截断输入 |端到端 forward snapshot |
| 优化与训练 | softmax、cross entropy、gradient clipping、AdamW、学习率调度 | 对照实现、数值稳定性测试、训练曲线 |
| 工程化 | checkpoint、序列化、性能、提交边界 | checkpoint 恢复、耗时、提交记录 |

### 4.3 对我们系统的关键启发

CS336 仓库中的 `AGENTS.md` 明确要求 AI 作为教学助教，不作为解题器；特别禁止直接写作业代码、伪代码、补全 TODO、编辑学生仓库、运行作业命令或提供第三方实现。因此我们的学习系统必须把以下内容设计成一等数据：

- 学习者自己的问题和当前理解。
- 学习者自己写出的假设。
- 失败测试、错误信息和诊断过程。
- 具体的 shape / 数值 / 性能 / round-trip 证据。
- 从“会运行”到“能解释”的知识成熟度。
- AI 回复使用了哪一种教练模式，以及是否越过了帮助边界。

## 5. 推荐的学习闭环

### 5.1 双闭环

现有规划系统继续负责执行闭环：

```text
目标 -> 周计划 -> 时间块 -> 任务执行 -> 复盘
```

新增学习系统负责知识闭环：

```text
来源 -> 模块 -> 学习会话 -> 尝试 -> 证据 -> 知识卡片 -> 主动回忆 -> 迁移应用
```

两条闭环通过以下对象连接：

- 学习主题关联学习来源和模块。
- 学习会话可以关联 Vikunja 任务和时间块。
- 证据可以关联代码仓库 commit、测试名称、实验结果或阅读来源。
- 复盘同时总结执行偏差和知识理解偏差。

### 5.2 一次学习会话的标准流程

1. **设定目标**：本次只解决一个可验证问题。
2. **阅读 / 观察**：记录来源、章节、commit 或文件位置。
3. **先写自己的理解**：在看 AI 解释前写出假设、形状、边界或预测。
4. **实际尝试**：在学生自己的代码仓库中实现、运行测试或做小实验。
5. **记录失败**：保存失败测试、错误、输入、预期和实际结果。
6. **请求教练帮助**：选择苏格拉底提问、概念提示、错误诊断或代码审查模式。
7. **验证修正**：用测试、不变量、toy example、数值对照或性能数据验证。
8. **提炼知识卡片**：用自己的话写出结论、适用条件、失败模式和证据。
9. **安排复习**：生成一个主动回忆问题，而不是只标记“已读”。
10. **连接计划**：创建下一步任务或下一次学习时间块。

## 6. 建议的数据对象

### 6.1 学习来源 `LearningSource`

保存：

- 标题、类型、URL、仓库地址。
- 版本或 commit SHA，避免链接内容变化后无法复现。
- 来源说明、许可证 / 使用边界、最后检查时间。
- 可引用的章节、文件、行号或锚点。

### 6.2 学习路径 `LearningTrack` 与模块 `LearningModule`

保存：

- 学习目标和预期能力。
- 模块顺序、前置知识、状态和完成证据。
- 模块关联的来源、任务和知识卡片。

CS336 示例模块可以是：

1. 环境与测试工作流。
2. 数据采样与语言建模输入。
3. Tokenizer 与 BPE。
4. PyTorch 神经网络原语。
5. Attention、mask 与 RoPE。
6. Transformer block 与 language model。
7. Optimizer、学习率和 checkpoint。
8. 结果解释、性能和迁移实验。

### 6.3 学习会话 `StudySession`

保存：

- 目标、模块、开始 / 结束时间。
- 本次问题、预期结果、开始前理解。
- 尝试摘要、阻塞点、完成状态。
- 关联的 Planner task / time block。
- 学习者自己的总结和下一步。

### 6.4 知识卡片 `KnowledgeCard`

一张卡片不只是标题和摘要，至少需要：

- 一句话定义。
- 为什么重要。
- 用自己的话解释。
- 最小例子和反例 / 失败模式。
- 前置知识和相关卡片。
- 来源引用。
- 证据引用。
- 成熟度：`observed`、`understood`、`verified`、`applied`、`teachable`。
- 置信度和待解决问题。

### 6.5 证据 `Evidence`

证据可以是：

- pytest 测试名和结果。
- 代码仓库 commit。
- toy input / output。
- shape、数值、性能或训练曲线。
- 阅读来源的章节定位。
- 复述或讲解记录。

知识卡片必须能回答“我为什么相信这句话”，否则只能算候选笔记。

### 6.6 主动回忆 `ReviewItem`

保存：

- 回忆问题。
- 期望覆盖的知识卡片。
- 上次回答、评分和错误类型。
- 下一次复习时间。
- 是否完成过迁移应用。

第一版不必马上实现完整 Anki 算法；先实现手动 / 简单间隔队列即可。

## 7. AI 教练模式

首期建议把 AI 能力拆成明确模式，而不是一个无边界的聊天框：

| 模式 | 允许做什么 | CS336 默认 |
|---|---|---|
| `Socratic` | 一次问一个澄清问题，暴露理解缺口 | 默认 |
| `Concept Hint` | 解释概念、提示相关不变量和边界 | 默认 |
| `Debug Guide` | 帮助读错误、设计实验和定位层次 | 默认 |
| `Code Review` | 评价用户已有代码的风险和测试缺口 | 默认 |
| `Synthesis` | 把用户自己的记录整理成知识卡片草稿 | 默认 |
| `Recall Quiz` | 出主动回忆题并评价回答 | 默认 |
| `Direct Solution` | 直接给实现或补 TODO | CS336 禁止 |

每次 AI 交互需要保存：

- 使用的模式。
- 输入上下文来源。
- AI 给出的提示 / 问题。
- 用户采取的行动。
- 最终证据和结果。

这样后续可以复盘“AI 是否帮助我学会了”，而不是只统计对话次数。

## 8. 方案候选与取舍

### 方案 A：SQLite-only 知识库

- **优点**：查询、筛选、复习队列和 UI 关系最直接。
- **缺点**：知识内容的 Git diff 不自然；导出和长期可读性需要额外设计。
- **风险**：很容易变成只保存字段、不保存思考过程的管理后台。

### 方案 B：结构化索引 + Git Markdown 知识资产，推荐

- SQLite 保存来源、模块、会话状态、关系、复习时间和任务关联。
- `learning/` 保存学习日志、知识卡片、实验记录和阶段总结。
- 每个 Markdown 文件有稳定 ID，数据库只保存索引与状态。
- **优点**：符合项目的 Git 追踪要求；内容可读、可 diff、可迁移；AI 上下文边界清晰。
- **缺点**：需要处理文件索引、重命名、删除和数据库状态同步。
- **风险**：如果一开始做实时双向同步，会复杂化；首期应采用显式“保存 / 索引 / 导出”。

### 方案 C：外部 Logseq / AppFlowy + 当前项目做编排层

- 外部工具保存笔记和知识图谱，本项目只保存计划、链接和复习任务。
- **优点**：可以快速获得成熟编辑器和反向链接体验。
- **缺点**：学习上下文、证据和复习状态分散；同步和备份边界复杂；AI 教练难以可靠地读取结构化证据。
- **风险**：最终形成两个系统，无法知道哪个是事实来源。

### 初步推荐

推荐方案 B，但第一阶段只实现最小混合边界：

```text
SQLite：来源 / 模块 / 会话索引 / 复习状态 / Planner 关联
Git Markdown：学习日志 / 知识卡片 / 实验记录 / 阶段总结
```

暂不做向量数据库、自动网页爬取、全量 PDF 复制和自动知识图谱推断。

## 9. CS336 实际操作示例

### 9.1 创建学习路径

建立学习主题：

```text
CS336 Assignment 1 - Basics
目标：能够解释并亲自实现一个最小 Transformer LM 的关键组件，
     并能用测试与实验解释失败原因。
```

绑定来源：

- Assignment 1 GitHub 仓库。
- 仓库固定 commit SHA。
- Assignment PDF / README / tests / `AGENTS.md`。
- Stanford CS336 课程页面。

### 9.2 以 Attention 模块为例

一次会话不记录“我看了 Attention”，而记录：

```text
问题：
为什么 attention score 要缩放？mask 应该在 softmax 前还是后生效？

开始前预测：
我认为输出形状应当是 ...
我认为被 mask 的位置应当满足 ...

尝试：
我写了自己的实现，运行了目标测试。

证据：
测试名称、失败输出、toy tensor、shape 检查、修正后的测试结果。

知识卡片：
用自己的话解释缩放、归一化、mask 和多头拆分。
记录一个会导致错误结果的反例。

复习题：
如果 query / key / value 的长度不同，哪些维度应该保持不变？
```

AI 在这个过程中的作用是：

1. 先检查用户的预测是否完整。
2. 只给一个下一步可验证的问题。
3. 帮用户设计 toy example 或 shape assertion。
4. 根据用户提供的错误和代码做诊断。
5. 在测试通过后要求用户自己解释为什么通过。

AI 不直接替用户写 `tests/adapters.py` 或作业实现。

### 9.3 由学习回到规划

每个模块都可以自动生成：

- 一个学习任务。
- 一个 60-90 分钟时间块建议。
- 一个会话记录。
- 一个完成证据。
- 一个复习问题。
- 一个周复盘条目。

这样“学习计划”和“知识沉淀”不是两套流程。

## 10. 第一阶段建议验收标准

第一阶段只需要证明以下闭环成立：

- 能创建一个学习来源，并固定 URL / revision。
- 能创建一个学习路径和有序模块。
- 能开始一个学习会话，并关联现有任务 / 时间块。
- 能记录开始前理解、尝试、问题、证据和会话结论。
- 能把会话结论提升为知识卡片，并关联来源和证据。
- 能为知识卡片创建主动回忆问题并记录一次复习。
- 能在 Today / Review 中看到学习投入与学习产出。
- 能导出学习索引和 Markdown 知识资产。
- 测试数据库和个人数据库继续隔离。
- CS336 模式下不会提供直接作业实现、TODO 补全或自动编辑。

## 11. 明确暂缓

- 向量数据库、embedding、RAG 和自动问答。
- 自动爬取整个 GitHub 仓库或课程 PDF。
- 自动把所有阅读内容拆成知识图谱。
- 完整 Anki 算法和复杂记忆模型。
- 浏览器扩展、IDE 插件和多端实时协作。
- 自动修改学生代码、自动运行作业命令或自动提交。

1. 是否接受“SQLite 结构化索引 + Git Markdown 知识资产”作为第一版架构。
